# Chantier 1 — Socle : plan d'implémentation

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Socle multi-serveurs : config `.env`, SQLite + migrations, permissions fines, réseau de serveurs, audit + routage des logs, panel web (Fastify + React/shadcn-admin) avec OAuth2 Discord et console en direct, lanceur avec versions installables et rollback, CI GitHub Actions.

**Architecture:** Un process `launcher.js` (modules natifs uniquement) supervise l'application (`src/index.js`) en process enfant, via IPC. L'application contient le bot discord.js et le serveur Fastify. Toute la logique métier est dans `src/core/`, qui reçoit la DB et un « exécuteur Discord » par injection. Le panel React est compilé dans `web/dist` et servi par Fastify.

**Tech Stack:** Node ≥ 20.12 (ESM, `process.loadEnvFile`), discord.js 14, better-sqlite3, Fastify 5 (+ @fastify/cookie, @fastify/static, @fastify/websocket, @fastify/rate-limit), selfsigned, `node --test`. Panel : React 19, Vite, TypeScript, TanStack Router/Query/Table, shadcn/ui (base satnaing/shadcn-admin).

## Global Constraints

- Node `>=20.12` (`process.loadEnvFile`).
- Config uniquement via `.env.dev` / `.env.prod` (+ variables d'environnement prioritaires). `OWNER_ID` : un seul ID, 17–20 chiffres, toutes les permissions, non modifiable depuis le panel.
- `src/core/` n'importe jamais `discord.js`, `fastify` ni `src/bot|web`.
- `launcher.js` n'utilise que des modules `node:*`.
- Toute route API déclare une permission ; vérification côté serveur.
- Actions sensibles : `confirm: true` exigé.
- Cookies session : `HttpOnly`, `SameSite=Strict`, `Secure` si HTTPS ; TTL 12h, inactivité 2h.
- Pas de saisie de commandes dans la console.
- Style JS : tabs, `stroustrup`, virgules pendantes (eslint existant).
